# 10.7 冻结 MLP 策略

这是 2026-10-07 实验训练、在 10 月 8 日完成检验的冻结网络。此目录是独立模型材料：不修改游戏规则，不替换当前默认 AI，也不改动项目构建入口。

## 文件与使用

- `policy.bin`：C++ 推理权重，原始冻结文件，无重新训练或转换修改。
- `checkpoint.pt`：同一版本的 PyTorch 检查点，含 actor、critic、训练配置。仅加载可信来源的检查点。
- `neural-policy.hpp`：仅依赖 C++20 标准库的 CPU 推理，无 PyTorch 或 GPU 运行时要求。
- `predict.cpp`：独立推理示例；从标准输入读取 718 个状态浮点数和 156 个合法动作掩码值，输出动作索引。
- `observation-schema.json`、`actions.json`：状态布局和动作索引定义。
- `manifest.json`：权重校验值、训练设置、测试范围和限制。
- `verify_inference.py`：用 NumPy 独立校验 C++ logits 和合法动作掩码，仅使用合成输入。

在本目录中编译：

```sh
g++ -std=c++20 -O3 predict.cpp -o predict
./predict policy.bin < encoded-state.txt
python verify_inference.py ./predict
```

Windows 将可执行文件名换为 `predict.exe`。校验脚本需要 NumPy。程序输出的是 `actions.json` 的 `index`，不是技能枚举值；游戏接入方负责按 schema 编码状态、用引擎生成合法动作掩码，再将结果提交给游戏。

`Policy::choose(..., false)` 按掩码后的 softmax 概率采样，与正式测试一致。改成 greedy 会改变策略，不能直接沿用下面的胜率。

## 网络与训练

网络为 `718 → 512 → 512 → 512`，三层 Tanh；actor 输出 156 个动作 logits，critic 输出一个局面价值。训练参数共 973,981 个，C++ 文件只包含决策所需的 actor 和共享层。训练方法是 masked PPO，对手是搜索预算 1,000 的调参 AI，64 个环境、每次采样 64 步、60 次更新，共 245,760 个环境步、18,804 个完整对局。

**本模型不是 Zero 自我对弈模型。** 它针对固定调参对手训练，存在对手适应性过强的问题。后续 Zero 实验应使用独立目录和随机初始化，不能把本检查点作为预训练。

## 测试结果与适用边界

冻结后，对搜索预算 4,000 的调参 AI：1,000 局，982 胜、17 负、1 平，胜率 98.2%，Wilson 95% 区间 97.17%–98.86%。两个座位各 500 局；平局计入分母；上限 100 回合，没有超时对局。`evaluation-summary.json` 保留汇总。

另一次冻结后与助手的娱乐检验：0 胜、20 负、0 平。这 20 局没有用于训练。本模型的高基准胜率不能代表对人类或所有策略的普遍强度；对缓慢积蓄资源等打法可出现过度献祭、无效防守。

**上述训练和测试使用的是 `4c73b1db87c75e565bb025d058aea1278ca693c4` 加本地修复的引擎，不是该提交的原始规则。** 本地修复包括：双方蓄力先统一检测再生成反击、战矛追加攻击的数组引用失效修复、三连刺后续代价仅扣当前血量，以及第二玩家输入权限检查。鲜血印记和资源转换打断行为保持实验当时的实现。这些引擎修复不随本目录提交。

因此，原始主分支接入本网络后，胜率和行为需要重新测试。schema 固定保留实验中的 10 个标记槽和 8 个回调阶段槽；缺少新增枚举的引擎也不能直接缩短输入维度。延迟超过 5 回合的事件合并到最后一格，部分效果只编码数量。可参数化动作的 N 限制为 0–16；合法性由调用方的引擎决定。该目录提供模型推理材料，不宣称完整游戏接入或训练重现已经完成。

对局过程中模型不在线学习。不附带用户对局、助手逐步对局、服务器凭据或远程连接文件。
